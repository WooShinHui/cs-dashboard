컴파일 타임 — 코드가 기계어로 바뀌기 전
플레이 버튼 누르기 훨씬 전. 빌드할 때.
UHT (Unreal Header Tool)가 먼저 실행
컴파일러보다 먼저 실행됨. 너의 .h 파일에서 UCLASS(), UPROPERTY(), UFUNCTION() 매크로를 파싱해서 .generated.h 파일을 자동 생성함.
// WarriorBaseCharacter.h에 네가 쓴 것:
UPROPERTY(VisibleAnywhere, BlueprintReadOnly)
UWarriorAbilitySystemComponent* WarriorAbilitySystemComponent;

// → UHT가 .generated.h에 메타데이터 코드 생성
// → 런타임에 "이 클래스에 ASC라는 컴포넌트가 있다"를 엔진이 알게 됨
🎮 엘든링 비유: 게임 설치할 때 "이 보스는 HP가 있고, 이 공격 패턴이 있다"는 정보를 미리 메타데이터로 만들어두는 단계. 아직 게임 실행 전.
C++ 컴파일러가 실제 컴파일
UHT가 만든 .generated.h + 너의 코드 → 합쳐서 컴파일. 이때 #include 순서, 상속 관계가 확정됨.
⚠️ 여기서 결정되는 것: AWarriorHeroCharacter는 AWarriorBaseCharacter의 자식이다. BaseCharacter의 생성자가 Hero보다 반드시 먼저 호출된다. 이건 C++ 언어 규칙.

void GiveToAbilitySystemComponent(ASC, Level) {
// OnGiven 어빌리티 → 부여 즉시 자동 실행 (패시브 등)
GrantAbilities(ActivateOnGivenAbilities, ASC, Level);

GrantAbilities(ReactiveAbilities, ASC, Level);
}

ASC가 Tag 매칭으로 어빌리티 탐색 → 활성화
등록된 모든 어빌리티를 순회. 각 Spec의 DynamicAbilityTags에 InputTag.EquipAxe가 있는 GA를 찾아 실행.
void UWarriorAbilitySystemComponent::OnAbilityInputPressed(const FGameplayTag& InInputTag) {
if (!InInputTag.IsValid()) return;
for (const FGameplayAbilitySpec& Spec : GetActivatableAbilities()) {
// ★ 핵심: DynamicAbilityTags에 이 InputTag가 있는지 확인
if (!Spec.DynamicAbilityTags.HasTagExact(InInputTag)) continue;
TryActivateAbility(Spec.Handle);
}
}

Q: "GAS 초기화 순서를 설명해주세요"
A: "생성자에서 CreateDefaultSubobject로 ASC와 AttributeSet을 생성하고, PossessedBy에서 InitAbilityActorInfo로 ASC를 초기화합니다. 그 다음 StartUpData에서 기본 어빌리티를 부여하는데, OnGiven Policy면 즉시 실행되고, OnTriggered면 입력 대기 상태로 등록됩니다."

Q: "입력이 어빌리티로 연결되는 과정은?"
A: "Enhanced Input의 InputAction을 GameplayTag와 쌍으로 DataAsset에 정의합니다. 키 입력 시 해당 Tag가 ASC의 OnAbilityInputPressed로 전달되고, ASC는 등록된 어빌리티의 DynamicAbilityTags에서 매칭되는 것을 찾아 TryActivateAbility를 호출합니다. Tag 기반이라 새 스킬 추가 시 C++ 수정이 필요 없습니다."
